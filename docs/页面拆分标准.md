# 页面拆分标准（Page Object Model）

> **核心原则**：一个页面 = 一个类 = 一个业务功能

---

## 🎯 页面拆分决策树

```
开始分析页面
    ↓
┌─────────────────────────────┐
│ 是否有独立的 URL？           │
└─────────────────────────────┘
    ├─ 是 → ✅ 独立页面
    └─ 否 → 继续分析
        ↓
┌─────────────────────────────┐
│ 是否完成独立的业务功能？     │
└─────────────────────────────┘
    ├─ 是 → ✅ 独立页面
    └─ 否 → 继续分析
        ↓
┌─────────────────────────────┐
│ 页面元素是否完全不同？       │
└─────────────────────────────┘
    ├─ 是 → ✅ 独立页面
    └─ 否 → 继续分析
        ↓
┌─────────────────────────────┐
│ 是否需要独立测试？           │
└─────────────────────────────┘
    ├─ 是 → ✅ 独立页面
    └─ 否 → ❌ 合并到父页面
```

---

## ✅ 需要拆分的情况

### 1. 不同的 URL 路径

```python
# ✅ 正确：每个 URL 对应一个页面
class LoginPage(BasePage):
    # URL: /dataapp/login
    pass

class IdentitySelectPage(BasePage):
    # URL: /dataapp/login#/identity
    pass

class MyDataPage(BasePage):
    # URL: /dataapp/index#/jssjzx/grsjzx/myarchive
    pass
```

---

### 2. 不同的业务功能

```python
# ✅ 正确：按业务功能拆分
class LoginPage(BasePage):
    """负责：用户登录、身份验证"""
    def login(self): ...

class MyDataPage(BasePage):
    """负责：查看档案、导出数据"""
    def view_archive(self): ...
    def export_archive(self): ...

class DataQueryPage(BasePage):
    """负责：数据查询、结果过滤"""
    def query_data(self): ...
    def filter_results(self): ...
```

---

### 3. 页面元素完全不同

```python
# 登录页元素
login_elements = {
    "username": "#username",
    "password": "#password",
    "login_btn": "#loginBtn"
}

# 我的数据页元素
my_data_elements = {
    "search_input": "#search",
    "export_btn": "#export",
    "data_table": "#dataTable"
}

# ✅ 元素完全不同 → 不同页面
```

---

### 4. 需要独立测试

```python
# ✅ 可以独立测试的场景应该拆分
def test_login():
    # 只测试登录功能
    login_page.login("user", "pass")
    assert login_page.is_logged_in()

def test_select_identity():
    # 只测试身份选择功能
    identity_page.select_identity("教师")
    assert identity_page.is_selected()
```

---

## ❌ 不需要拆分的情况

### 1. 同一页面的不同操作

```python
# ✅ 正确：都在同一个页面类中
class MyDataPage(BasePage):
    def query_data(self): ...      # 查询操作
    def export_data(self): ...     # 导出操作
    def filter_data(self): ...     # 过滤操作
    def edit_data(self): ...       # 编辑操作
    # 这些都在同一个页面，不需要拆分
```

---

### 2. 简单弹窗/对话框

```python
# ✅ 简单弹窗不需要独立页面
class MyDataPage(BasePage):
    def confirm_delete(self):
        self.page.click("text=确定")
    
    def cancel_delete(self):
        self.page.click("text=取消")
```

```python
# ❌ 复杂弹窗需要独立页面
class DeleteConfirmDialog(BasePage):
    def confirm(self): ...
    def cancel(self): ...
    def get_warning_message(self): ...
    def get_affected_items(self): ...
```

---

### 3. 页面内的小组件

```python
# ✅ 页面内的小组件不需要独立页面
class DataQueryPage(BasePage):
    def fill_search_input(self, text): ...
    def click_search_button(self): ...
    def clear_search(self): ...
    # 搜索框只是页面的一部分
```

## 🎯 页面粒度标准

### 粗粒度拆分（推荐 ⭐⭐⭐）

```python
pages/
├── login_page.py           # 所有登录相关（~200 行）
├── my_data_page.py         # 所有我的数据相关（~300 行）
├── data_query_page.py      # 所有数据查询相关（~250 行）
└── teacher_manage_page.py  # 所有教师管理相关（~350 行）
```

**优点**：
- ✅ 文件数量少（易于导航）
- ✅ 符合业务直觉
- ✅ 维护成本低

**缺点**：
- ❌ 单个文件可能较大（200-400 行）

**适用范围**：90% 的项目

---

### 中粒度拆分（特殊情况 ⭐⭐）

```python
pages/
├── login/
│   ├── login_form.py       # 登录表单（~100 行）
│   └── identity_select.py  # 身份选择（~100 行）
├── my_data/
│   ├── view_archive.py     # 查看档案（~150 行）
│   └── edit_archive.py     # 编辑档案（~150 行）
└── query/
    ├── simple_query.py     # 简单查询（~100 行）
    └── advanced_query.py   # 高级查询（~150 行）
```

**优点**：
- ✅ 文件较小（<200 行）
- ✅ 职责更单一

**缺点**：
- ❌ 文件数量多
- ❌ 导航成本增加

**适用范围**：
- 页面非常复杂（>500 行）
- 团队规模大（多人协作）

---

### 细粒度拆分（避免 ⭐）

```python
pages/
├── login/
│   ├── username_input.py   # ❌ 过度拆分
│   ├── password_input.py   # ❌
│   └── login_button.py     # ❌
```

**问题**：
- ❌ 文件数量爆炸
- ❌ 维护成本极高
- ❌ 违背 POM 初衷

**结论**：**不要这样做！**

## 📊 页面大小标准

### 推荐指标

| 指标 | 推荐值 | 警告值 | 危险值 |
|------|-------|-------|-------|
| **代码行数** | <300 行 | 300-500 行 | >500 行 |
| **公共方法数** | <10 个 | 10-15 个 | >15 个 |
| **元素定位器** | <20 个 | 20-30 个 | >30 个 |
| **私有方法数** | <10 个 | 10-20 个 | >20 个 |

### 超过警告值怎么办？

**选项 1: 提取公共方法**
```python
# ❌ 重复代码
def method1(self):
    self.page.click("#btn1")
    self.page.wait_for_selector("#result1")

def method2(self):
    self.page.click("#btn2")
    self.page.wait_for_selector("#result2")

# ✅ 提取公共方法
def click_and_wait(self, btn_selector, result_selector):
    self.page.click(btn_selector)
    self.page.wait_for_selector(result_selector)
```

**选项 2: 拆分子页面**
```python
# ❌ 太大（600 行）
class TeacherManagePage(BasePage):
    # ... 600 行代码

# ✅ 拆分
class TeacherListPage(BasePage):
    # 列表相关（250 行）

class TeacherDetailPage(BasePage):
    # 详情相关（250 行）

class TeacherEditPage(BasePage):
    # 编辑相关（200 行）
```

**选项 3: 使用组件模式**
```python
class TeacherManagePage(BasePage):
    def __init__(self, page):
        super().__init__(page)
        self.search = SearchComponent(page)
        self.table = TableComponent(page)
        self.pagination = PaginationComponent(page)
```

## 🎯 页面命名规范

### 类命名

```python
# ✅ 正确：功能 + Page
class LoginPage(BasePage)
class MyDataPage(BasePage)
class DataQueryPage(BasePage)
class TeacherManagePage(BasePage)

# ❌ 错误
class Login()                    # 缺少 Page 后缀
class MyDataController()         # 不是 Controller
class LoginPageObject()          # 太啰嗦
```

---

### 文件命名

```python
# ✅ 正确：小写 + 下划线
login_page.py
my_data_page.py
data_query_page.py

# ❌ 错误
LoginPage.py                     # 大写开头
loginpage.py                     # 缺少下划线
login-page.py                    # 使用中划线
```

---

### 方法命名

```python
# ✅ 正确：动词开头
def login(self, username, password): ...
def select_identity(self, identity): ...
def query_data(self, criteria): ...
def export_data(self, format): ...

# ❌ 错误
def user_login(self): ...        # 缺少动作
def do_login(self): ...          # do 前缀多余
def login_action(self): ...      # action 后缀多余
```

## 📝 页面类结构模板

```python
"""页面说明"""
from pages.base_page import BasePage
from playwright.sync_api import Page
from utils.logger import logger


class MyPage(BasePage):
    """
    页面名称
    
    功能说明:
    - 功能 1
    - 功能 2
    
    URL:
    - /path/to/page
    """
    
    # ===== 元素定位器（必填）=====
    # 使用大写命名，按功能分组
    
    # 输入框
    SEARCH_INPUT = "#search"
    NAME_INPUT = "#name"
    
    # 按钮
    SEARCH_BUTTON = "#searchBtn"
    EXPORT_BUTTON = "#exportBtn"
    
    # 表格
    DATA_TABLE = "#dataTable"
    
    # ===== 初始化方法 =====
    def __init__(self, page: Page, base_url: str = ""):
        super().__init__(page, base_url)
    
    # ===== 页面方法（公共 API）=====
    # 使用小写命名，动词开头
    
    def query_data(self, keyword: str) -> "MyPage":
        """
        查询数据
        
        Args:
            keyword: 查询关键词
        
        Returns:
            self
        """
        logger.info(f"查询数据：{keyword}")
        return (self
            .fill(self.SEARCH_INPUT, keyword)
            .click(self.SEARCH_BUTTON))
    
    def export_data(self, format: str = "excel") -> "MyPage":
        """
        导出数据
        
        Args:
            format: 导出格式（excel/csv）
        
        Returns:
            self
        """
        logger.info(f"导出数据：{format}")
        return self.click(self.EXPORT_BUTTON)
    
    def get_data_count(self) -> int:
        """
        获取数据条数
        
        Returns:
            数据条数
        """
        rows = self.page.locator(f"{self.DATA_TABLE} tr").all()
        return len(rows)
    
    # ===== 辅助方法（可选）=====
    # 以 _ 开头的私有方法
    
    def _wait_for_table_loaded(self, timeout: int = 5000):
        """等待表格加载完成"""
        self.page.wait_for_selector(self.DATA_TABLE, timeout=timeout)
```

## 🔧 页面重构检查清单

### 什么时候需要重构？

- [ ] 单个文件超过 500 行
- [ ] 单个类超过 15 个公共方法
- [ ] 定位器超过 30 个
- [ ] 方法长度超过 50 行
- [ ] 重复代码出现 3 次以上
- [ ] 类名包含 "And" 或 "With"（如 `LoginAndSelectPage`）

---

### 重构策略

**策略 1: 提取方法**
```python
# Before
def method1(self):
    # 50 行代码
    
def method2(self):
    # 50 行代码，其中 30 行与 method1 重复

# After
def _common_logic(self):
    # 提取公共逻辑

def method1(self):
    self._common_logic()
    # 剩余 20 行

def method2(self):
    self._common_logic()
    # 剩余 20 行
```

**策略 2: 提取类**
```python
# Before
class HugePage(BasePage):
    # 800 行代码

# After
class PagePart1(BasePage):
    # 300 行

class PagePart2(BasePage):
    # 300 行

class PagePart3(BasePage):
    # 200 行
```

**策略 3: 使用组件**
```python
# Before
class ComplexPage(BasePage):
    # 600 行代码

# After
class ComplexPage(BasePage):
    def __init__(self, page):
        super().__init__(page)
        self.header = HeaderComponent(page)
        self.sidebar = SidebarComponent(page)
        self.content = ContentComponent(page)
```

## 🎯 总结

### 核心原则
1. **一个页面 = 一个类 = 一个业务功能**
2. **按业务模块拆分，不按技术拆分**
3. **粗粒度优先，避免过度设计**

### 决策流程
```
URL 不同？ → 是 → 拆分
    ↓
功能不同？ → 是 → 拆分
    ↓
元素不同？ → 是 → 拆分
    ↓
需要独立测试？ → 是 → 拆分
    ↓
否 → 合并
```

### 推荐实践
- ✅ 按业务模块组织目录
- ✅ 公共页面放在 `common/`
- ✅ 单个文件 <300 行
- ✅ 单个类 <10 个公共方法
- ✅ 使用粗粒度拆分

---

**遵循这个标准，你的测试框架会清晰、易维护！** 🦐
