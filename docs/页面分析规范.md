# 页面分析规范（SOP）

## ⚠️ 重要原则

**❌ 错误做法（本末倒置）**：
```
猜测定位器 → 写页面对象 → 写测试 → 失败 → 才分析页面
```

**✅ 正确做法**：
```
分析页面 → 提取定位器 → 写页面对象 → 写测试 → 通过
```

### 步骤 4: 编写页面对象

基于分析结果编写 `pages/common/login_page.py`：

```python
class LoginPage(BasePage):
    """登录页面 - 基于实际页面分析"""
    
    # ===== 元素定位器（已验证）=====
    USERNAME_INPUT = "input[placeholder*='用户名']"
    PASSWORD_INPUT = "input[placeholder*='密码']"
    VERIFY_CODE_INPUT = "input[placeholder*='验证码']"
    VERIFY_CODE_IMAGE = "img[src*='verifyCode']"
    LOGIN_BUTTON = "button:has-text('登录')"
    FORGOT_PASSWORD_LINK = "a:has-text('忘记密码')"
    ERROR_MESSAGE = ".error-message"
    
    # ===== 页面方法 =====
    def login(self, username: str, password: str, verify_code: str = "2222"):
        """
        执行登录
        
        Args:
            username: 用户名
            password: 密码
            verify_code: 验证码（默认 2222）
        
        Returns:
            self
        """
        logger.info(f"登录：用户={username}")
        
        (self
         .fill(self.USERNAME_INPUT, username, "用户名")
         .fill(self.PASSWORD_INPUT, password, "密码")
         .fill(self.VERIFY_CODE_INPUT, verify_code, "验证码")
         .click(self.LOGIN_BUTTON, "登录按钮"))
        
        return self
```

## 💡 最佳实践

### 定位器优先级

1. **用户可见属性**（最稳定）
   - `placeholder` 文本
   - `button:has-text('登录')`
   - `aria-label`

2. **语义化属性**
   - `name` 属性
   - `role` 属性
   - `aria-*` 属性

3. **ID/Class**（可能变化）
   - `#username`
   - `.login-input`

4. **CSS/XPath**（最后选择）
   - `div > input:nth-child(2)`
   - `//input[@name='username']`

### 定位器验证

**不要猜测！永远基于实际页面！**

```python
# ❌ 错误：猜测
USERNAME_INPUT = "#username"

# ✅ 正确：基于实际分析
USERNAME_INPUT = "input[placeholder*='用户名']"  # 已验证
```

## 📝 总结

**核心原则**：
> **先分析，后编码**
> 
> **永远不要猜测元素定位器！**

**标准流程**：
```
打开页面 → 分析结构 → 提取定位器 → 编写代码 → 验证测试
```

**质量保证**：
- 每个定位器都有实际页面依据
- 每个测试用例都有页面能力支撑
- 每次失败都能追溯到分析文档
