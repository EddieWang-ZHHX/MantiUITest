# 页面拆分量化标准

> **核心原则**：用数据说话，不用主观判断

---

## 📊 量化评估框架

### 4 个评估维度

| 维度 | 权重 | 评分标准（1-3 分） |
|------|------|------------------|
| **URL 差异** | 40% | 3 分：父路径不同<br>2 分：子路径不同<br>1 分：相同路径 |
| **功能独立性** | 30% | 3 分：完全独立<br>2 分：相关但可独立<br>1 分：强依赖 |
| **元素重叠率** | 20% | 3 分：重复率<30%<br>2 分：重复率 30%-70%<br>1 分：重复率>70% |
| **测试独立性** | 10% | 3 分：可独立测试<br>2 分：需要少量前置<br>1 分：强依赖 |

### 决策公式

```
总分 = URL 得分×0.4 + 功能得分×0.3 + 元素得分×0.2 + 测试得分×0.1

决策：
- 总分 ≥ 2.5 → ✅ 拆分
- 总分 < 2.5 → ❌ 合并
```

## 📝 评估示例

### 示例 1: 登录页 vs 身份选择

**输入数据**：
```python
page1_url = "/dataapp/login"
page2_url = "/dataapp/login#/identity"
page1_func = "登录"
page2_func = "身份选择"
page1_elements = 6
page2_elements = 4
page1_methods = 5
page2_methods = 3
```

**评估过程**：

1. **URL 差异**：
   - 父路径相同（都是 `/dataapp/login`）
   - 但完整 URL 不同（有 `#/identity`）
   - **得分：2.0 分**

2. **功能独立性**：
   - 身份选择依赖登录
   - 不能独立存在
   - **得分：1.0 分**（查依赖表）

3. **元素重叠率**：
   - 元素数量差异：|6-4|/6 = 33%
   - **得分：2.0 分**

4. **测试独立性**：
   - 方法总数：5+3=8
   - **得分：2.0 分**

**计算总分**：
```
总分 = 2.0×0.4 + 1.0×0.3 + 2.0×0.2 + 2.0×0.1
     = 0.8 + 0.3 + 0.4 + 0.2
     = 1.7 分
```

**决策**：
```
1.7 < 2.5 → ❌ 建议合并
```

**结论**：身份选择应该合并到登录页，作为登录页的一个方法。

## 🎯 评分细则

### 1. URL 差异评分

| 情况 | 得分 | 示例 |
|------|------|------|
| 父路径不同 | 3.0 | `/login` vs `/data` |
| 父路径相同，子路径不同 | 2.0 | `/data/query` vs `/data/export` |
| URL 完全相同 | 1.0 | `/login` vs `/login#/step2` |

**代码逻辑**：
```python
def get_parent_path(url: str) -> str:
    url = url.split('#')[0].split('?')[0]
    parts = url.strip('/').split('/')
    return '/' + parts[0] if parts else '/'

parent1 = get_parent_path(url1)
parent2 = get_parent_path(url2)

if parent1 != parent2:
    score = 3.0
elif url1 != url2:
    score = 2.0
else:
    score = 1.0
```

---

### 2. 功能独立性评分

| 情况 | 得分 | 示例 |
|------|------|------|
| 完全独立的业务功能 | 3.0 | 登录 vs 查询 |
| 相关但可独立存在 | 2.0 | 查询 vs 导出 |
| 强依赖，不能独立 | 1.0 | 登录 vs 身份选择 |

**代码逻辑**：
```python
DEPENDENCY_MAP = {
    ('登录', '身份选择'): 1.0,  # 强依赖
    ('查询', '导出'): 2.0,      # 相关但独立
    ('查询', '编辑'): 3.0,      # 完全独立
}

key = (func1, func2)
if key in DEPENDENCY_MAP:
    score = DEPENDENCY_MAP[key]
else:
    score = 3.0  # 默认独立
```

---

### 3. 元素重叠率评分

| 情况 | 得分 | 计算方式 |
|------|------|---------|
| 重复率 < 30% | 3.0 | 差异比例 > 70% |
| 重复率 30%-70% | 2.0 | 差异比例 30%-70% |
| 重复率 > 70% | 1.0 | 差异比例 < 30% |

**代码逻辑**：
```python
diff_ratio = abs(count1 - count2) / max(count1, count2)

if diff_ratio > 0.7:
    score = 3.0
elif diff_ratio > 0.3:
    score = 2.0
else:
    score = 1.0
```

**注意**：这是简化评估，使用元素数量差异作为代理指标。更精确的方法是实际比较元素定位器。

---

### 4. 测试独立性评分

| 情况 | 得分 | 判断标准 |
|------|------|---------|
| 可完全独立测试 | 3.0 | 方法总数 ≥ 10 |
| 需要少量前置条件 | 2.0 | 方法总数 5-9 |
| 强依赖其他页面 | 1.0 | 方法总数 < 5 |

**代码逻辑**：
```python
total_methods = methods1 + methods2

if total_methods >= 10:
    score = 3.0
elif total_methods >= 5:
    score = 2.0
else:
    score = 1.0
```

## 📊 决策阈值说明

### 为什么选择 2.5 分？

**阈值分析**：

| 阈值 | 拆分倾向 | 适用场景 |
|------|---------|---------|
| 2.0 | 容易拆分 | 大型项目，多人协作 |
| 2.5 | 平衡 | 中型项目（推荐） |
| 3.0 | 倾向合并 | 小型项目，快速迭代 |

**推荐 2.5 的理由**：
- ✅ 平衡了拆分和合并
- ✅ 避免过度设计
- ✅ 保持代码可维护性

---

## 🔍 边界情况处理

### 情况 1: 总分正好 2.5 分

**决策**：✅ 建议拆分

**理由**：阈值是"≥2.5"，包含边界。

**示例**：
```
总分 = 2.5 → ✅ 拆分
```

---

### 情况 2: 某个维度分数争议

**解决方案**：调整权重或手动覆盖

```python
# 如果你认为 URL 差异更重要
WEIGHTS = {
    'url': 0.5,      # 提高到 50%
    'function': 0.3,
    'elements': 0.1, # 降低到 10%
    'test': 0.1
}
```

---

### 情况 3: 工具评估与实际不符

**原因**：
- 依赖关系表不完整
- 元素数量统计不准确
- 特殊业务场景

**解决方案**：
1. 更新 `DEPENDENCY_MAP`
2. 手动调整分数
3. 以实际维护体验为准
